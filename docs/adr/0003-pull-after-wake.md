# ADR 0003：唤醒后拉取，不做常驻推送通道

状态：已采纳（2026-11-02，实现属 Phase 1）

## 背景

后台限制持续收紧：Android 14 起开机广播不能拉起麦克风型前台服务，Android 15 又扩大到数据同步等类型；静默高优先级消息可能被厂商降级。把"实时收"当默认会在真机上随机失效。

## 决定

- 设备到云是**出站长连**（WSS），设备不开入站端口。
- FCM 高优先级 data 消息只带 `{hint:"pull"}`，不带内容；设备醒来后用 HTTPS 拉取 inbox。
- 投递语义至少一次；设备按信封 `id` 去重，保证幂等。
- 重启后唤醒监听不能自动恢复，必须由用户可见的动作恢复；**不把"重启自动恢复唤醒词"写进验收标准**。
- 需要后台主动出声的提醒走闹钟/通知通道，不指望后台 TTS。

## 后果

延迟上限取决于唤醒通道（p95 目标写进阶段 1 验收）。没有真实设备的这段时间，只能在 device-sim 上验证拉取与去重逻辑。
